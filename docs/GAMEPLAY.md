# Gameplay Systems

## Match Flow

Lobby → Entry Validation → Loadout → Hunt Start → Clue Chain → Exploration → NPC/Tool Decisions → Timed Objective → Validation → Ranking → Rewards → Replay/Analysis.

## Map Monetization

Maps should sell information or convenience, not guaranteed victory.

Possible map products:

- starter regional map;
- terrain map;
- transit map;
- clue-density map;
- historical/lore map;
- temporary event map;
- fragment packs;
- map upgrades;
- team map-sharing license.

Found maps remain important so free/low-spend players retain viable paths.

## Tool Monetization

Tool categories:

- clue analysis;
- navigation;
- protection;
- time management;
- traversal;
- communication/team coordination;
- Easter-egg discovery.

Tools can be consumable, rechargeable, persistent, earned, rented, event-limited or collectible.

## Puzzle Design

Every major clue should define:

- source;
- intended interpretation;
- answer;
- accepted variants;
- difficulty;
- hint ladder;
- tool interactions;
- NPC interactions;
- validation method;
- spectator-safe display state.

## Easter-Egg Design

Use three layers:

1. **Discoverable:** attentive solo players can find it.
2. **Deep:** requires cross-referencing music, lore or environments.
3. **Community:** intentionally difficult and designed for collective investigation.

## Multiplayer Dynamics

Potential mechanics:

- temporary alliances;
- teams;
- resource trading;
- information trading;
- controlled sabotage;
- shared puzzles;
- race objectives;
- territory/route competition;
- social deduction around unreliable NPCs.

Cash-prize modes should use carefully constrained sabotage mechanics and server-authoritative validation.

## Fairness

A competitive player should be able to understand why they won or lost. Randomness, AI behavior, tool effects and purchased advantages must be bounded and auditable.
